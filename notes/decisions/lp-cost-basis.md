# Cost basis от LP закрытия

## Контекст

Когда пользователь закрывает LP-позицию, токены приходят на кошелёк через
`lp_remove`. По умолчанию `cost_basis_tracker` либо игнорировал такие токены,
либо брал текущую spot-цену через `m.usd`. В обоих случаях исходный депозит
LP-позиции «терялся» — реальный убыток LP не отражался в средней цене актива.

Пример: депозит $240 в V3 ETH/USDC. Цена выходит вниз → закрыли, на руках
0.110 ETH. По default-логике cost basis ETH сместился бы на $1900 (spot).
Реальный cost basis должен быть `$240 / 0.110 = $2 187` (для трейдера это
точка безубытка).

## Решение

В `cost_basis_tracker.ts` добавлен двухпроходный алгоритм
`attributeLpCloses()`.

### Pass 1 — группировка
Ключ группы: `${protocolId}|${chain}` (одна позиция на протокол × сеть).

- `lp_add`: `group.depositUsd += Σ amount × hist_price`
- `lp_remove`: `group.closes.push({ ins, totalUsd })` где `totalUsd` —
  USD-стоимость возвращаемых токенов на момент закрытия

### Pass 2 — атрибуция
Для каждого `lp_remove`:
```
share = closeUsd / Σ closeUsd_всех_закрытий_позиции
attributedCostUsd = depositUsd × share
```
Распределяется между IN-токенами пропорционально их USD-весу. Используется
как `paidUsd` в `tracker.buy()` вместо spot.

### Корректность для разных сценариев

| Сценарий | Депозит | Закрытие | Cost basis |
|---|---|---|---|
| Выход вниз, 100% в ETH | $260 | 0.105 ETH | $2 476/ETH ✓ |
| Выход вверх, 100% в USDC | $260 | 300 USDC | $0.867/USDC ✓ |
| Два частичных закрытия | $260 | 2× 0.05 ETH | $2 600/ETH ✓ |

## Ограничения

Группировка по `protocolId + chain` — две Uniswap V3 позиции в разной паре
на одной сети объединяются. Точное разделение требует tokenId, который
DeBank в `lp_add/lp_remove` не отдаёт. В будущем можно использовать
RPC-индекс из Этапа 3.

## UI

В `RegistryPage` под каждым `lp_remove` синий бейдж
«cost basis +$X» — показывает атрибуцированную сумму.
