# Протокол аудита позиций — с обратной связью во всю систему

> Команда «проведи аудит всех позиций» / «проверь кошелёк». Цель аудита — НЕ
> только пополнить эталоны и найти баги, а **системно улучшать всю платформу**:
> каждый аудит должен оставлять доработки для классификатора, серверного движка,
> детектора аномалий, golden-датасета и знаний для дообучения. Конечная цель
> протокола — чтобы после каждого аудита система становилась точнее и
> самопроверяемее (3× recurrence loop закрывается автоматически).

## Часть A — Ядро аудита (что делаем с КАЖДОЙ позицией)

Поколоночный аудит по 21 столбцу от **реестра операций** (`chain_operations`) +
источников (DeBank/Krystal/Etherscan/Alchemy) + эталонов. 6 слоёв проверки,
per-column вердикт **OK / WARN / FAIL** + root cause + фикс.

**Железные правила (из опыта):**
- Сверять с **реестром операций**, НЕ только с golden/клиентом — иначе пропустишь
  случай «server==client, но оба неверны» (Alice PT-плечо 2026-06-04).
- Cost basis = **сколько реально уплачено** (out-side USDC), НЕ receipt-спот токена.
- Не выдавать вердикт по cost basis без полного **многоходового трейса** (receipt
  → underlying → исходные покупки).
- LP → сверять с Krystar Σ deposit; non-LP → WAC lot-trace.

## Часть B — ⭐ Обратная связь в систему (ОБЯЗАТЕЛЬНЫЙ финальный слой)

Каждая находка (FAIL/WARN) аудита должна быть **смаршрутизирована** в нужный слой
системы и породить **≥1 durable-артефакт**. «Отметили и забыли» — запрещено.

| Тип находки | → Куда дорабатываем | Артефакт |
|---|---|---|
| Операция мисклассифицирована (op_type/notes/protocol неверны) | **Классификатор** | правило/heuristic + classifier-тест |
| Cost basis / PnL неверны, корень в движке | **Сервер/движок** (`@cap-flow/ucb`) | фикс + failing-тест ДО фикса |
| Симптом, который можно ловить автоматически | **Детектор аномалий** | новый чек ИЛИ тюнинг порога + unit-тест |
| Проверенное правильное значение | **Golden-датасет** | эталон в 3 слоя (DB + ledger + память) |
| Паттерн «как считать этот тип позиции» | **Знания для дообучения** | запись в ledger + memory (корм классификатору/детектору) |
| Расхождение источников / провенанс | **Карта источников** ([[capflow_data_source_authority]]) | обновить authority-map |

### Принципы маршрутизации
1. **Ручная находка → детектор обязан научиться ловить её сам.** Если баг нашли
   глазами, но детектор его не видит — это дыра детектора (заводим чек), иначе рецидив.
2. **Новый/изменённый чек детектора → прогнать по аудированному аккаунту → 0
   ложных.** Чек, который шумит на заведомо-корректных позициях — не годен (урок
   `cost_basis_from_spot`: ложно срабатывал на M6 priced-not-trusted; перевели на
   `priceSource==='fallback'`).
3. **Различать «классификатор vs движок vs порт».** Один симптом может иметь корень
   в разных слоях — трейсить до конкретного. Пример: GMX receipt cost basis сломан →
   корень оказался НЕ в классификаторе (notes верны), а в **непортированном на
   сервер `linkAsyncDeposits`** (порт). Маршрут — в движок, не в классификатор.
4. **Golden — это «заморозка правды», детектор — «автопроверка», классификатор —
   «правильный вход».** Аудит кормит все три из одного разбора.

## Часть C — Worked example: аудит Alice 2026-06-04 (эталон применения Части B)

Один аудит 12 позиций Alice породил доработки во ВСЕХ слоях:

| Находка | Маршрут | Артефакт |
|---|---|---|
| GMX receipt (GLV/GM) cross-protocol cost basis = receipt-спот | Движок | `981c9d0` порт async-linker + проверка реестром |
| PT-залог на занятый стейбл = receipt-спот | Движок | `137141d` borrowed-stable = уплаченный номинал |
| V3: дубликат/пропажа NFT одной пары | Движок | `cc90579` детерминированный матч по nftId (DeBank description) |
| `cost_basis_from_spot` шумит на receipt-декомпозиции | Детектор | `75ca947` чек → `priceSource==='fallback'` (0 ложных) |
| `fee_apr_without_fee` ловит флоат-пыль | Детектор | noise-floor 0.1% |
| 12 позиций выверены от реестра | Golden | ledger `alice-2026-06-04.md` + DB + память |
| Паттерны GMX/Pendle/Avantis/Morpho ops | Знания | разбор в ledger (корм классификатору/детектору) |
| golden-дедуп по неуникальному ключу | Система (БД) | миграция `0032` + обязательный positionKey |

### Кандидаты-чеки детектора, выведенные из этого аудита
- `receipt_collateral_cost_below_paid` — receipt-залог, у которого startUsd <
  Σ(уплаченных стейблов/underlying на закуп) сверх допуска. Ловил бы ОБА cost-basis
  бага, включая случай server==client (по реестру, не по golden).
- `leverage_collateral_borrow_funded` — плечевой залог на заёмные средства:
  проверять, что cost basis = уплаченный номинал, не receipt-спот.
